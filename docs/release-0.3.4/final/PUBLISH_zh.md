# 0.3.4 发布操作清单

已完成的本地准备：冻结验收后的安装包；中英文发布正文；统计范围、推荐参数与实验性说明；Windows 原始检查与契约证据；维护者确认 Linux 通过的记录；公开附件、源文件恢复快照和 SHA256 清单。其他平台不再作为本轮发布前提，也不宣称已验证。

以下是正式发布时的剩余操作，本次准备未执行：

1. 在本目录运行 `python verify_release.py`。核对安装包 SHA256 必须为 `8B1A8940101997492D4F3E2AFE696717BFE63CC9905FE91E225A3534754B997D`。不要换成重新打包的同名文件。
2. 在预定发布分支审阅并提交 0.3.4 源码、测试、帮助、指南及当前 CI 配置。provenance/repository-paths.txt 列出恢复快照选中的路径，含原来未跟踪的 fast_hetero 和 native 文件。该清单限定本次版本内容，不代表授权纳入其他研究数据或整份工作区。
3. 运行 `python verify_release.py --repo <仓库目录> --git-ref <候选提交>`。它应确认候选提交中的所选源文件与冻结快照一致。当前旧 HEAD 不符合此要求；通过后才把 `v0.3.4` 指向该提交并推送分支/tag。Tag 名是预定值，本轮没有创建。
4. 在目标 GitHub 仓库创建 Release，标题为 `fastphylosig 0.3.4`，选择已核验的 `v0.3.4`，使用 RELEASE_NOTES_en.md 或 RELEASE_NOTES_zh.md 的正文。安装包附件使用本目录确切归档，可另附材料 ZIP 与 SHA256SUMS.txt。自动生成的 source ZIP/TAR 不替代已验收的 R CMD build 包。
5. 发布后核对下载附件的 SHA256，并做一次干净库安装/加载检查；记录 URL、实际 tag 提交和发布日期。后续更新网站时使用本版范围说明，不把 D/Δ 实验性功能改称确认性方法，也不把历史性能表改标为本版新计时。

如果另行决定向 CRAN 提交，使用本目录相同安装归档和 cran-comments.md 草稿，并先处理早先 0.3.1 提交的实际状态。此步骤单独执行；本轮不推断现有审核状态、不重复提交，不将公开 GitHub 发布表述为 CRAN 接受。维护者邮箱按决定继续使用 DESCRIPTION 中的 GitHub noreply 地址。
